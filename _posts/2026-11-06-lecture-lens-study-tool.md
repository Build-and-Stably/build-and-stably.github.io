회사에 다니면서 사이버대학교에서 소프트웨어 공부를 하고 있습니다. 이 분야가 처음이라 이번 학기 중간고사에서 SQL 과목과 데이터베이스 과목 모두 평균보다 크게 낮은 점수를 받았습니다. F를 피하려면 기말고사에서 90점 정도는 받아야 합니다. AI 노트 도구로 만든 문제로 공부해 봤지만 효과가 없었습니다. 그래서 제 상황에 맞는 공부 도구를 Claude Code와 함께 직접 만들었습니다.

필요한 것은 네 가지였습니다.

- 몇십 쪽짜리 강의 슬라이드를 **요약 없이 원문 그대로** 적은 쪽수로 보기
- 교수님 강의 스크립트까지 한 파일에 넣고, **PDF 안에서 글자 검색** 하기
- 시험이 전부 4지선다라서, **강의자료에 근거한 객관식 문제**를 많이 풀기
- 강의자료는 외부에 함부로 올리지 않기

## 한 일

1. **원문 압축 PDF를 만들었습니다.** 슬라이드 글자를 그대로 옮기고 `[원본 p.12]`처럼 원래 쪽수를 붙였습니다. 주차마다 교수님 스크립트를 뒤에 붙이고, 지금까지 배운 주차를 합친 누적본도 만듭니다. 한 주차는 슬라이드 54쪽이 약 10쪽이 됐습니다.
2. **문제은행을 만들었습니다.** SQL 과목 3개 주차에서 주차마다 4지선다 30문항, 모두 90문항을 만들었습니다. 문제마다 근거가 되는 쪽수와 원문 문장을 붙였습니다.
3. **근거 검사기를 만들었습니다.** 문제에 붙은 원문 문장이 강의자료에 실제로 있는지 하나씩 대조합니다. AI가 그럴듯하게 지어낸 근거는 여기서 걸러집니다.
4. **휴대폰용 문제풀이 화면을 만들었습니다.** 파일 하나짜리 웹 페이지라 인터넷 없이 열립니다. 연습, 모의고사, 오답노트 모드가 있고, 틀린 문제는 연속 두 번 맞혀야 오답노트에서 빠집니다.

## 왜 이렇게 결정했나

- **요약 대신 원문 그대로:** 요약을 하면 시험에 나올 문장이 빠질 수 있습니다. 그래서 글자는 그대로 두고, 모든 쪽에 반복되는 머리말과 쪽번호만 지웠습니다. 애니메이션 때문에 같은 내용이 두 번 나오는 쪽은 하나로 합쳤습니다.
- **처리는 내 PC에서, AI는 문제 만들 때만:** PDF 변환과 문제풀이 화면은 모두 내 PC 안에서 처리합니다. AI로 가는 것은 문제를 만들 때 쓰는 추출 텍스트뿐이고, 계정 설정에서 학습 사용을 꺼 두었습니다.
- **휴대폰에는 파일로 직접 옮기기:** 문제풀이 화면을 웹 링크로 올리면 편하지만, 문제와 원문 문장이 서버에 남습니다. 그래서 파일을 휴대폰에 직접 옮겨 오프라인으로 쓰기로 했습니다. 문제가 늘어날 때 기록이 사라지지 않게 "기록 코드"로 옮기는 기능을 넣었습니다.
- **GitHub에는 코드만:** 강의자료와 결과물(추출 텍스트, PDF, 문제은행)은 올라가지 않게 막았습니다.

## 어려웠던 점

- **띄어쓰기가 전부 사라졌습니다.** 처음 뽑은 글이 "테이블을생성하는세부적인방법을"처럼 붙어 나왔습니다. 확인해 보니 이 PDF는 띄어쓰기를 공백 문자 대신 **글자 사이를 조금 더 벌리는 방식**으로 표현하고 있었습니다. 그래서 글자 사이 간격을 재서 공백을 다시 넣었습니다. 글자 간격을 좁힌 문단은 기준이 달라서, 그 줄의 평소 간격보다 얼마나 더 벌어졌는지를 보도록 다시 고쳤습니다.
- **스크립트가 한 덩어리였습니다.** 자동 자막이라 한 주차가 59,000자짜리 한 문단이었습니다. 글자는 그대로 두고 "~니다", "~요" 같은 문장 끝에서 약 400자마다 문단만 나눴습니다.
- **정답만 유독 긴 보기가 있었습니다.** 90문항 중 8문항은 정답에만 이유가 붙어 있어서, 내용을 몰라도 가장 긴 보기를 고르면 맞는 문제였습니다. 네 보기의 길이를 비슷하게 맞추고, 이런 문제를 검사기가 자동으로 잡게 했습니다.
- **보기를 섞으면 해설 번호가 틀렸습니다.** 해설에 "①은 틀리다"라고 적혀 있어도 화면에서는 그 보기가 ④일 수 있습니다. 해설 속 번호를 화면 순서에 맞춰 바꿔 보여주도록 고쳤습니다.
- **커밋에 실제 이메일이 들어갔습니다.** 비공개 저장소였지만, GitHub가 주는 공개되지 않는 주소로 바꿔 다시 올렸습니다.

## 11월 9일 추가: 읽기 쉬운 정리본

강의자료에서 뽑은 텍스트는 내용은 다 들어 있었지만 막상 읽으려니 너무 불편했습니다. 슬라이드 글자가 "PRIMARY / KEY"처럼 줄마다 끊겨 있었고, 쪽마다 과목 이름 같은 머리말이 반복됐고, SQL 코드와 설명이 구분 없이 섞여 있었습니다. 교수님 스크립트는 400자짜리 문단이 100개 넘게 이어진 글 덩어리였습니다. 그래서 공부할 때 읽는 용도의 "정리본"을 따로 만들었습니다.

### 한 일

1. **한 주차로 견본을 먼저 만들었습니다.** 어떻게 바꿀지 저도 아이디어가 없어서, SQL 9주차 하나만 먼저 바꿔 보고 마음에 드는지 확인했습니다. 소단원마다 카드를 하나씩 두고, 원래 슬라이드 쪽수를 달고, 코드는 코드 상자에, 표는 표로 정리했습니다.
2. **교수님 말씀을 세 겹으로 넣었습니다.** "시험", "꼭", "중요"라고 하신 문장은 노란 상자에 그대로 옮겼고, 긴 설명은 몇 줄로 요약했고, 스크립트 원문은 접어 두었다가 눌러서 펼쳐 볼 수 있게 했습니다.
3. **원고를 화면으로 바꾸는 기능을 만들었습니다.** 정리 내용은 간단한 글 원고로 쓰고, 명령 한 번으로 휴대폰에서도 보기 좋은 웹 페이지 파일로 바꿉니다. 이때 빠뜨린 스크립트 문단이나 쪽이 있으면 경고합니다.
4. **나머지 11개 주차는 나눠서 동시에 만들었습니다.** 견본이 마음에 들어서 네 과목 9~11주차를 모두 바꾸기로 했고, 보조 작업자 다섯 명에게 과목별로 나눠 맡겼습니다.
5. **끝나고 직접 검사했습니다.** 스크립트 문단이 하나도 빠지지 않았는지, "교수님 강조"로 옮긴 문장 73개가 원문과 글자까지 같은지 확인했습니다.

### 왜 이렇게 결정했나

- **추출 텍스트는 그대로 두고 따로 만들기:** 문제 근거 검사기는 추출 텍스트와 글자 그대로 대조합니다. 여기를 보기 좋게 고치면 검사가 흔들리니, 읽기용 파일을 따로 두었습니다.
- **요약과 원문을 함께:** 요약은 AI가 쓴 것이라 틀릴 수 있습니다. 그래서 요약 줄마다 스크립트 문단 번호를 달고, 바로 아래에 원문을 접어 두어 언제든 확인할 수 있게 했습니다.
- **다른 점은 감추지 않고 표시:** 슬라이드와 교수님 말씀이 다르거나, 자동 자막이 틀린 것 같거나, 슬라이드에는 없고 수업 시간에만 나온 중요한 내용은 빨간 상자로 따로 표시했습니다.
- **과목마다 다르게:** 스크립트가 없는 두 과목은 시험이 슬라이드 문장에서 단어만 바꿔 나온다고 해서, 요약이나 보충 설명 없이 슬라이드 문장과 숫자를 원래 표현 그대로 두고 정리만 했습니다.
- **인터넷 링크 대신 파일:** 문제풀이 화면처럼 파일 하나짜리라 휴대폰에 옮기면 인터넷 없이 열립니다. 강의 내용이 들어 있어서 GitHub에도 올리지 않게 막았습니다.

### 어려웠던 점

- **깨진 표:** PDF에서 뽑을 때 표 안 글자가 "smalli nt", "h varc ar"처럼 부서진 곳이 있었습니다. 원래 글자로 되살리되, 원본 PDF와 대조해 보라는 표시를 남겼습니다.
- **그림 속 글자:** 코드나 도식이 그림으로만 들어 있는 쪽은 글자를 뽑을 수 없었습니다. 내 PC에서 쪽을 이미지로 바꿔 보고 옮겨 적은 뒤 "그림에서 옮김"이라고 표시했습니다.
- **수업 시간에만 나온 내용:** 실습 시간에 교수님이 직접 보여 주신 옵션이나 오류 원인처럼 슬라이드에 없는 내용이 꽤 많았습니다. 이런 내용은 요약에 넣고 따로 눈에 띄게 표시했습니다.
