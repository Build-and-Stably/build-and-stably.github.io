교수학습센터에서 일하다 보면 다른 대학이 무엇을 하는지 늘 궁금합니다. 어느 대학이 새 교수법 워크숍을 열었는지, RISE 사업(지역혁신중심 대학지원체계)으로 무엇을 시작했는지, 교육부가 어떤 발표를 했는지 같은 것들입니다. 다른 대학의 공격적인 사업은 대부분 보도자료로 나오기 때문에, 기사만 잘 챙겨 봐도 흐름이 보입니다.

문제는 이 소식들이 여기저기 흩어져 있다는 점이었습니다. 구글 알리미 메일, 교육부 누리집, 대학 전문 언론 몇 곳을 따로따로 들어가 봐야 했습니다. 그래서 **매일 아침 이 소식들을 한 페이지에 모아 동료들과 함께 보는 웹페이지**를 만들었습니다.

## 처음 생각한 것과 실제로 가능한 것

처음에는 머릿속에 있는 소식 창구를 모두 넣고 싶었습니다.

- 구글 알리미(키워드 알림 메일)
- 교육부, 전문대교협, 대교협, KERIS 같은 기관의 뉴스레터와 공지
- 한국대학신문, 대학저널, 교수신문 같은 대학 전문 언론

AI와 함께 하나씩 따져 보니 가져오는 방법이 소식 창구마다 달랐습니다.

- **RSS가 있는 곳은 쉽습니다.** RSS는 사이트가 "새 글 목록"을 기계가 읽기 좋은 형태로 내놓는 주소입니다. 대학 전문 언론 세 곳 모두 RSS가 있었고, 같은 날 베리타스알파와 에듀진도 더해 다섯 곳이 되었습니다.
- **구글 뉴스는 검색어만 바꾸면 RSS가 됩니다.** "교수학습센터", "RISE 전문대학" 같은 검색어를 넣으면 구글 알리미와 거의 같은 효과를 냅니다.
- **교육부 누리집에서는 RSS를 찾지 못했습니다.** 대신 정부 보도자료가 모이는 정책브리핑을 구글 뉴스 검색으로 받고, 제목에 교육·대학 관련 단어가 있는 것만 남겼습니다.
- **RSS가 없는 기관 게시판**은 화면을 직접 읽어 오는 방식(스크래핑)이 필요합니다.
- **이메일 뉴스레터**는 메일함을 프로그램이 읽게 해야 해서 가장 복잡합니다.

## 범위를 줄인 결정

- **이메일 뉴스레터는 뺐습니다.** 어차피 같은 내용이 제 메일함으로 이미 오고 있었습니다. 페이지에까지 넣을 이유가 크지 않았습니다.
- **스크래핑도 뺐습니다.** 사이트 구성이 언제 어떻게 바뀔지 아무도 모릅니다. 바뀔 때마다 고쳐야 하는 구조는 혼자 관리하기 어렵다고 판단했습니다.
- 그래서 **공식 RSS와 뉴스 검색만** 쓰기로 했습니다. 덜 욕심내는 대신 오래 고장 없이 돌아가는 쪽을 골랐습니다.

## 동료와 공유하는 방법

혼자 보는 것이 아니라 센터 동료들과 함께 보고 싶었습니다. 그러려면 제 PC가 꺼져 있어도 매일 알아서 갱신되어야 했습니다.

- **선택**: GitHub Pages(무료로 웹페이지를 띄워 주는 서비스)와 GitHub Actions(정해진 시간에 프로그램을 대신 실행해 주는 기능)를 썼습니다.
- **동작 방식**: 매일 06:30과 12:30에 GitHub 서버가 수집 프로그램을 실행합니다. 새 기사를 모아 저장하면 페이지에 자동으로 반영됩니다.
- **고민했던 점**: 무료로 쓰려면 페이지가 공개여야 합니다. 하지만 올라가는 것은 이미 언론에 공개된 기사의 제목·요약·링크뿐이라 괜찮다고 봤습니다. 기사 본문은 저작권 때문에 싣지 않고 원문 링크로 연결합니다.

## 페이지에 넣은 것

- **분류 탭**: 교수학습, RISE·재정사업, AI·에듀테크, 정부·기관, 전문대학
- **같은 소식 묶기**: 한 대학의 보도자료를 여러 매체가 옮겨 실으면 5~7건이 줄줄이 뜹니다. 제목에 겹치는 단어와 대학 이름을 비교해 한 건으로 묶고, 나머지는 "같은 소식 n건 더 보기"로 접었습니다.
- **많이 언급된 대학**: 제목에서 대학 이름을 뽑아 기간별로 순위를 보여 줍니다. 누르면 그 대학 소식만 볼 수 있습니다.
- **필터가 담긴 주소**: "RISE·재정사업" 탭을 누른 상태의 주소를 보내면 동료도 같은 화면을 봅니다.
- **수집 상태 표시**: 어떤 소식 창구가 실패했는지 페이지 한쪽에 보입니다.

첫날 소식 창구 9곳에서 240여 건이 모였습니다.

## 어려웠던 점

- **정책브리핑 검색이 너무 넓었습니다.** "교육부"로 검색했는데 산림청·식약처 보도자료까지 잔뜩 들어왔습니다. 제목에 대학·교육 관련 단어가 있을 때만 남기도록 걸렀습니다.
- **대학 이름 뽑기가 생각보다 까다로웠습니다.** "○○대"로 끝나는 말을 찾으면 "전문대", "국립대", "지역의대" 같은 일반 명사도 함께 잡힙니다. 제외할 단어 목록을 따로 만들었습니다.
- **자동 실행 파일이 업로드되지 않았습니다.** 내 PC의 GitHub 로그인에는 자동 실행 설정을 올릴 권한이 없었습니다. 그 파일 하나만 GitHub 웹에서 직접 만드는 것으로 해결했습니다.

## 11월 9일 추가: 분류 넓히기와 '뉴스레터' 탭

### 분류를 넓히고 잡음 걸러 내기

맡은 업무가 교수학습·매체활용에서 교육과정과 원격교육(원격강좌)까지 넓어졌습니다. 그래서 상단 분류에 **교육과정**, **원격교육**을 더하고 관련 검색어도 넣었습니다.

그랬더니 사이버대학 홍보 기사, 평생교육원 모집 기사 같은 잡음이 많이 들어왔습니다. 그래서 **제목 제외어** 설정을 만들었습니다. 제목에 특정 단어가 있으면 빼는데, "수업", "교육과정" 같은 단어가 함께 있으면 남기는 예외도 둘 수 있게 했습니다.

### 공문으로 오는 뉴스레터도 같이 보고 싶었습니다

기사 말고도 학교 공문으로 다른 대학의 혁신지원사업 뉴스레터(PDF)가 꾸준히 옵니다. 내용이 알찬데 파일을 하나하나 열어 보기가 번거로웠습니다. 바라는 것은 세 가지였습니다.

- 기사와 뉴스레터는 **따로** 보기
- 뉴스레터 안에서 **CTL(교수학습)·AI 이야기가 나오면 먼저** 보기
- PDF는 구글 드라이브 폴더 하나에 모아 두기만 하면 끝

### 한 일

1. 구글 클라우드 콘솔에서 **서비스 계정**(프로그램 전용 구글 계정)을 만들었습니다. 뉴스레터 폴더 하나만 이 계정에 '뷰어'로 공유해서, 프로그램은 그 폴더만 읽을 수 있습니다.
2. 폴더의 PDF를 내려받아 글자를 뽑고, CTL·AI 핵심어가 나온 문장을 쪽 번호와 함께 찾는 프로그램을 새로 만들었습니다.
3. 페이지 위에 **[기사] / [뉴스레터] 탭**을 두었습니다. 뉴스레터 탭은 CTL·AI 문장이 있는 호를 위에, 나머지는 아래에 제목만 보여 줍니다.
4. 매일 06:30·12:30 자동 수집에 뉴스레터 단계를 붙였습니다. **새로 올라온 파일만** 읽고, 같은 파일을 두 번 넣으면 한 번만 보여 줍니다.

처음 넣어 둔 뉴스레터 28개를 읽었고, 그중 20여 개에서 CTL·AI 관련 문장을 찾았습니다.

### 왜 이렇게 결정했나

- **드라이브 폴더 vs 메일함 직접 읽기**: 공문 첨부를 메일함에서 바로 읽는 방법도 있지만, 1차 때 이메일은 복잡해서 뺐던 터라 같은 이유로 피했습니다. 대신 PDF를 드라이브 폴더에 넣는 수고 한 번만 들이기로 했습니다.
- **어디까지 공개할까**: 페이지가 공개라서 뉴스레터 내용이 그대로 인터넷에 올라갑니다. 다른 대학이 이미 배포한 홍보용 뉴스레터라 관련 문장 전체를 보여 줘도 된다고 판단했습니다.
- **무료 OCR vs 유료 AI**: 파일을 확인해 보니 **절반 이상(28개 중 15개)이 글자 없이 이미지로만 된 PDF**였습니다. 그래서 OCR(그림 속 글자를 읽어 내는 기술)이 꼭 필요했습니다. Claude API로 읽으면 품질은 가장 좋지만 돈이 듭니다. 무료 OCR 프로그램인 Tesseract로도 "CTL·AI 이야기가 있는지"는 충분히 가려낼 수 있어서 무료 쪽을 골랐습니다. 결과적으로 이번 작업은 **전부 무료**로 돌아갑니다.
- **실패해도 기사는 그대로**: 뉴스레터 수집은 기사 수집과 다른 프로그램으로 나누고, 실패해도 기사 저장은 계속되게 했습니다.

### 어려웠던 점

- **컬러 배경이 OCR을 망쳤습니다.** 사람 눈에는 깨끗한 본문인데 거의 다 깨진 글자로 나왔습니다. 해상도, 읽는 방식, 흑백 변환을 바꿔 가며 시험해 보니 **흑백으로 바꾸기만 해도** 확인용 핵심어가 0개에서 8개 모두 잡혔습니다.
- **OCR이 'AI'를 '시'로 읽었습니다.** 한국어 OCR이 영어 AI를 한글 '시'나 'Al'로 읽는 일이 잦았습니다. "생성형시"처럼 확실한 문맥만 골라 바로잡았습니다. "서울 시 교육청"까지 고쳐 버리지 않게 조심했습니다.
- **글자마다 띄어 읽었습니다.** "교 수 학 습 센 터"처럼 한 글자씩 끊긴 줄은 붙이도록 했습니다. 그래도 이미지 쪽 문장에는 오탈자가 남아 있어서, 페이지에 "OCR은 오탈자가 있을 수 있다"고 적어 두었습니다.
- **비밀 키 관리.** 서비스 계정 키 파일을 프로젝트 폴더 안에 받아 두었는데, 저장소가 공개라 실수로 올라가면 큰일입니다. 가장 먼저 git이 그 폴더를 무시하도록 막고, 키는 GitHub의 비밀 저장소(Secrets)에만 넣었습니다.
- **자동 실행 파일 권한 문제가 또 나왔습니다.** 권한을 추가하는 인증이 오류로 실패해서, 이번에도 그 파일만 GitHub 웹에서 붙여 넣어 고쳤습니다.
- **내 PC와 GitHub 서버의 결과가 조금 달랐습니다.** OCR 프로그램 버전이 달라서, 서버에서 전부 다시 읽혀 비교했습니다. 실패 0건에 관련 뉴스레터 수도 비슷하게(22건 대 24건) 나왔습니다.
