대학에서 교수학습 지원 업무를 하다 보면 설문 결과, 강의평가 점수, 학습관리시스템(LMS)의 접속 기록 같은 데이터를 자주 만납니다. 숫자를 읽을 수는 있지만 "이 평균을 이렇게 말해도 되나?", "응답이 이만큼이면 믿어도 되나?" 같은 질문에는 늘 확신이 없었습니다. 그래서 **조사·통계 기초를 업무 장면에 연결해서 하루 10분씩 공부하는 휴대폰 앱**을 Claude Code와 함께 만들었습니다.

앞서 만든 교육공학 학습 앱이 너무 잘 맞아서 같은 방식으로 만들고 싶었습니다. 다만 이번에는 시험 준비가 아니라 **업무에서 데이터를 어떻게 쓸지 아이디어가 많이 떠오르는 것**이 목적입니다. 그래서 더 가볍게, 대신 "우리 업무라면?"이라는 질문을 매 회차마다 넣었습니다.

## 한 일

1. **바로 만들지 않고 제안부터 받았습니다.** 이전 앱에서 효과가 좋았던 방식 그대로, "마음대로 만들지 말고 먼저 제안해 달라"고 했습니다. AI가 폴더의 PDF 두 개(조사·통계 수험서의 필기 교재와 필답형 문제집 발췌본)와 이전에 만들어 둔 "데이터 10분 노트" 웹페이지(Claude 아티팩트)를 살펴보고, 기능 제안과 정해야 할 질문을 내놓았습니다.
2. **제 답변으로 방향을 바로잡았습니다.** 처음 제안은 시험 대비 쪽으로 기울어 있었습니다. 저는 "시험이 아니라 업무 적용을 이론과 연결해서 공부하려는 것"이라고 정정했고, 한 주를 학습 5회로만 구성하기로 했습니다. 교육공학 앱보다 가볍게 하고 싶어서 주간 정리와 누적 검토는 뺐습니다.
3. **8주 40회 개요를 만들었습니다.** 기존 아티팩트의 10회를 1~2주차로 가져오고, 3주차부터는 PDF에서 업무에 도움이 되는 부분만 골라 새로 구성했습니다. 4~8주차는 개요만 정해 두고 원고는 나중에 쓰기로 했습니다.
   - 1주 기본기 / 2주 문항과 로그 / 3주 표본과 조사 대상 / 4주 조사 방법 / 5주 기술통계 / 6주 추론통계 / 7주 비교와 관계 / 8주 업무 적용
4. **3주차 글부터 검토받았습니다.** 앱보다 글이 먼저입니다. 표집틀, 확률·비확률 표집, 표본크기와 오차범위, 비표본오차를 다뤘고, 읽어 보고 마음에 들면 앱 화면을 만들기로 했습니다.
5. **앱을 만들었습니다.** 오늘, 회차, 아이디어, 용어, 설정의 다섯 화면입니다.
   - 한 회차: 이론 카드 3장 → 내 업무에 연결 → 아이디어 메모 → 내 말로 써보기 → 퀴즈 3문제
   - 틀린 문제는 복습함에 모이고, 아이디어 메모는 모아서 검색하고 전체 복사할 수 있습니다.
   - 글자 크기, 다크 모드, 백업 파일 저장과 불러오기
6. **배포하고 휴대폰에 설치했습니다.** 코드는 새 비공개 GitHub 저장소에 올리고, 앱은 Cloudflare에 올려서 휴대폰 크롬의 "홈 화면에 추가"로 설치했습니다.

## 왜 이렇게 결정했나

- **"아이디어 메모"가 이 앱의 핵심입니다:** 공부한 개념이 업무에서 어디에 쓰일지 바로 적어 두지 않으면 금방 잊습니다. 매 회차 끝에 "내 업무의 설문에서 응답이 가장 적은 집단은 누구일까?" 같은 질문을 하나씩 두고, 답을 적으면 따로 모이게 했습니다. 나중에 업무 기획할 때 꺼내 볼 수 있습니다.
- **"내 말로 써보기":** 수험서의 필답형 문제(예: "표집틀의 의미를 쓰고 문제점을 설명하시오")를 서술 연습으로 바꿨습니다. 먼저 내 말로 적어 본 뒤 모범 답안의 핵심과 비교합니다. 점수는 매기지 않습니다. 쓰는 과정에서 이해가 정리되기를 기대했습니다.
- **수험서는 재구성만:** 책의 문장을 옮기지 않고, 개념을 제가 이해한 방식으로 다시 설명하고 문제도 새로 만들었습니다. 수험서 PDF는 저장소에도 올라가지 않도록 제외했습니다.
- **이론에 업무 장면을 붙이기:** 모든 회차에 "내 업무에 연결" 카드를 넣었습니다. 예를 들어 표집틀 회차에서는 "전체 교수에게 설문한다고 하지만 실제로 보낼 수 있는 곳은 메일링 목록뿐"이라는 장면을 다룹니다. 개념이 추상적으로 남지 않게 하려는 것입니다.
- **기존 앱은 건드리지 않기:** 이미 매일 쓰고 있는 교육공학 앱은 어떤 변경도 있으면 안 된다고 분명히 당부했습니다. 그래서 새 앱은 별도의 저장소와 별도의 Cloudflare 프로젝트로 만들고, 이전 앱의 폴더는 열어 보지도 않기로 했습니다. 필요한 틀은 이전에 만든 아티팩트에서 가져왔습니다.
- **빌드 도구 없이 단순하게:** 이전 앱은 React와 Vite를 썼지만, 이번에는 기본 HTML, CSS, 자바스크립트 파일만 썼습니다. 화면이 다섯 개뿐이라 빌드 과정이 오히려 부담이었습니다. 글 내용은 JSON 파일에 두고, 작은 스크립트가 앱이 읽는 파일 하나로 합칩니다.

## 어려웠던 점

- **브라우저 확인 도구가 연결되지 않았습니다.** 평소처럼 Chrome 확장으로 화면을 확인하려 했지만 연결이 안 됐습니다. 대신 화면이 없는 Chrome(헤드리스 모드)을 직접 실행해서 캡처했고, 시험용 페이지를 따로 만들어 글 열기, 메모 저장, 퀴즈 풀기, 다크 모드 전환을 자동으로 눌러 확인했습니다.
- **Cloudflare 명령이 바뀌어 있었습니다.** 새 프로젝트를 만들려고 예전 방식(Pages) 명령을 썼더니 실패했습니다. 지금은 Pages가 Workers 쪽으로 합쳐지는 중이라, "정적 파일 올리기" 방식으로 바꿔서 배포했습니다. 설정 파일은 다섯 줄이면 충분했습니다.
- **실수로 캐시 폴더가 저장소에 올라갔습니다.** 배포 도구가 만든 임시 폴더가 첫 커밋에 섞였습니다. 올라간 직후 발견해서 목록에서 빼고 무시 규칙에 추가했습니다. 비공개 저장소이고 비밀 정보는 아니었지만, "처음 올리기 전에 상태를 한 번 더 보자"는 교훈이 되었습니다.
- **PDF 글자가 깨져 있었습니다.** 스캔한 책이라 글자 인식 결과에 오타가 섞여 있었습니다. 그대로 쓰지 않고 목차와 핵심 개념을 파악하는 데만 쓰고, 문장은 직접 썼습니다.

## 작성한 코드

앱 코드와 설정은 약 400줄이고, 글 내용(JSON)이 약 1,100줄입니다. 글 내용 대부분은 기존 10회를 가져온 것이고, 이번에 새로 쓴 3주차 5회는 JSON 줄바꿈 기준으로 약 80줄입니다.
